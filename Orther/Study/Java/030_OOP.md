# OOP – Object-Oriented Programming

## 1. OOP là gì?

OOP (Object-Oriented Programming) – Lập trình hướng đối tượng là phương pháp lập trình tổ chức chương trình thành các đối tượng (Object), trong đó mỗi đối tượng chứa dữ liệu (Attributes) và các hành vi (Methods) liên quan đến dữ liệu đó.

OOP giúp chương trình có cấu trúc rõ ràng, dễ bảo trì, tái sử dụng và mở rộng.

### 1.1. Hai khái niệm cơ bản

- Class (Lớp): Là bản thiết kế định nghĩa các thuộc tính và phương thức của đối tượng.
- Object (Đối tượng): Là một thực thể cụ thể được tạo ra từ Class.

Ví dụ:

Class `Car` định nghĩa một chiếc xe gồm:

- Attributes: `brand`, `color`, `speed`.
- Methods: `start()`, `stop()`, `accelerate()`.

Từ Class `Car`, có thể tạo nhiều Object với trạng thái khác nhau.

## 2. Bốn tính chất của OOP

1\. Encapsulation – Đóng gói

Bảo vệ dữ liệu và kiểm soát quyền truy cập.

2\. Inheritance – Kế thừa

Tái sử dụng và mở rộng code từ Class cha.

3\. Polymorphism – Đa hình

Một phương thức có thể có nhiều cách thực thi.

4\. Abstraction – Trừu tượng

Ẩn chi tiết triển khai, chỉ cung cấp những gì cần thiết.

### 2.1. Encapsulation – Tính đóng gói

Định nghĩa:

Encapsulation là nguyên tắc đóng gói dữ liệu và các phương thức xử lý dữ liệu vào cùng một Class, đồng thời kiểm soát quyền truy cập vào dữ liệu đó.

Mục đích:

- Bảo vệ dữ liệu khỏi việc truy cập hoặc thay đổi không hợp lệ.
- Kiểm soát cách dữ liệu được đọc và cập nhật.
- Đảm bảo đối tượng luôn duy trì trạng thái hợp lệ.

Cách triển khai trong Java:

- Sử dụng `private` để hạn chế truy cập trực tiếp.
- Sử dụng Getter, Setter hoặc các phương thức nghiệp vụ để kiểm soát dữ liệu.

### 2.2. Inheritance – Tính kế thừa

Định nghĩa:

Inheritance là cơ chế cho phép một Class kế thừa các thuộc tính và phương thức từ Class khác, đồng thời có thể bổ sung hoặc mở rộng chức năng riêng.

Mục đích:

- Tái sử dụng code từ Class cha.
- Giảm trùng lặp code.
- Dễ dàng mở rộng và tổ chức các Class theo mối quan hệ phân cấp.

Cách triển khai trong Java:

- Sử dụng `extends` để kế thừa Class.
- Sử dụng `implements` để triển khai Interface.

### 2.3. Polymorphism – Tính đa hình

Định nghĩa:

Polymorphism là tính chất cho phép cùng một phương thức hoặc cách gọi có thể thực hiện những hành vi khác nhau tùy thuộc vào ngữ cảnh.

Mục đích:

- Tăng tính linh hoạt trong thiết kế chương trình.
- Giảm sự phụ thuộc vào Class triển khai cụ thể.
- Dễ dàng bổ sung các hành vi mới mà không cần thay đổi nhiều code hiện có.

Cách triển khai trong Java:

Có hai hình thức chính:

- Method Overloading (Compile-time): Nhiều phương thức cùng tên nhưng khác danh sách tham số.
- Method Overriding (Runtime): Class con định nghĩa lại phương thức được kế thừa từ Class cha.

### 2.4. Abstraction – Tính trừu tượng

Định nghĩa:

Abstraction là nguyên tắc chỉ thể hiện những đặc điểm và hành vi cần thiết của đối tượng, đồng thời ẩn đi các chi tiết triển khai bên trong.

Mục đích:

- Giảm độ phức tạp khi sử dụng hệ thống.
- Tách biệt cách sử dụng và cách triển khai.
- Giảm sự phụ thuộc giữa các thành phần.
- Dễ dàng thay đổi hoặc mở rộng cách triển khai.

Cách triển khai trong Java:

- `Abstract Class`: Dùng khi cần định nghĩa cấu trúc và chia sẻ logic chung giữa các Class.
- `Interface`: Dùng để định nghĩa một hợp đồng hành vi mà các Class cần triển khai.

## 3. Ví dụ thực tế tổng hợp

Ví dụ: Hệ thống thanh toán hỗ trợ Credit Card và Bank Transfer.

Payment (Interface)

pay(amount)

CreditCardPayment

Thanh toán thẻ

BankTransferPayment

Chuyển khoản

```
public interface Payment {
    void pay(double amount);
}

public class CreditCardPayment implements Payment {

    @Override
    public void pay(double amount) {
        System.out.println("Pay by Credit Card: " + amount);
    }
}

public class BankTransferPayment implements Payment {

    @Override
    public void pay(double amount) {
        System.out.println("Pay by Bank Transfer: " + amount);
    }
}
```

Sử dụng:

```
public class Main {
    public static void main(String[] args) {

        Payment payment = new CreditCardPayment();
        payment.pay(1000);

        payment = new BankTransferPayment();
        payment.pay(2000);
    }
}
```

Qua ví dụ này có thể thấy:

| Tính chất     | Thể hiện trong ví dụ                                                                      |
| ------------- | ----------------------------------------------------------------------------------------- |
| Encapsulation | Có thể đóng gói dữ liệu thanh toán và kiểm soát việc cập nhật thông tin                   |
| Inheritance   | Các Class có thể kế thừa một Class thanh toán chung nếu thiết kế theo Abstract Class      |
| Polymorphism  | Cùng gọi `pay()` nhưng mỗi phương thức thanh toán thực hiện khác nhau                     |
| Abstraction   | Interface `Payment` chỉ định nghĩa hành vi thanh toán, không quy định chi tiết triển khai |

Lưu ý: Ví dụ code trực tiếp ở trên minh họa rõ nhất Abstraction và Polymorphism; Encapsulation và Inheritance cần được bổ sung khi thiết kế đầy đủ hơn.

## 4. Tổng kết

| Tính chất     | Bản chất               | Mục đích chính      |
| ------------- | ---------------------- | ------------------- |
| Encapsulation | Đóng gói dữ liệu       | Bảo vệ dữ liệu      |
| Inheritance   | Kế thừa Class          | Tái sử dụng code    |
| Polymorphism  | Nhiều hành vi          | Tăng tính linh hoạt |
| Abstraction   | Ẩn chi tiết triển khai | Giảm độ phức tạp    |

Cách ghi nhớ khi phỏng vấn:

- Encapsulation: Protect Data.
- Inheritance: Reuse Code.
- Polymorphism: Many Behaviors.
- Abstraction: Hide Implementation Details.

Quan điểm của mình: Nên dùng phiên bản này làm tài liệu học chính. Định nghĩa đủ chuyên nghiệp để trả lời phỏng vấn, nhưng vẫn ngắn gọn để dễ hiểu và ghi nhớ. Sau khi nắm chắc 4 tính chất, hãy học sâu hơn về cách triển khai trong Java, đặc biệt là Interface, Abstract Class, Overloading và Overriding.
